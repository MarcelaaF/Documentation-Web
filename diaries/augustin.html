Week 8

Objectives Achieved

Worked on technical design manual

Continue testing to ensure all features are working as expected.

Objectives Achieved

Like the last few weeks, continued testing to ensure all features are working as expected.

Start on presentation slides for midpoint system demo.

Week 10

Objectives Achieved

Presented the midpoint system demo to the supervisor and received feedback.

⚠ Challenges

  • Had some poor time management and miscommunications, leading to our submission being late and messy as we had different timelines.

💡 Reflection

Appoint someone to QA all our submissions to ensure quality and consistency, and also ensure that everyone is one the same page, we should not be facing these kind of issues this late into the project.

Week 11

Objectives Achieved

Reviewed and tested the application's core functionalities across the User, Business Partner, and Admin roles.

Continued creating and refining test cases to ensure the core features meet their requirements.

⚠ Challenges

  • Some features were still being improved, making it difficult to complete certain test cases.

💡 Reflection

This week, I focused more on my role as a tester and realised how important it is to thoroughly check each feature before moving on to more advanced functionalities.

Week 12

Objectives Achieved

Continued testing the core functionalities and verifying fixes for previously identified bugs.

Updated relevant test cases and documentation, including the Document Control section.

⚠ Challenges

  • Some user stories needed further clarification before suitable test cases could be prepared.

💡 Reflection

By participating in discussions about advanced features, I gained a better understanding of how user stories are planned and how they can be translated into test cases. Our team communication has also improved compared to the earlier sprints.

Week 13

Objectives Achieved

Started preparing test cases for the advanced features assigned to Sprint 7.

Began testing newly implemented features and recording any bugs or unexpected results.

⚠ Challenges

  • Certain test cases could not be completed because their corresponding features were still under development.

💡 Reflection

As we started working on advanced features, I realised that creating detailed test cases requires a good understanding of the system's workflow. I had to think more carefully about different scenarios, including situations where users might enter incorrect information or perform unexpected actions.

Week 14

Objectives Achieved

Continued testing the advanced features implemented during Sprint 7.

Performed regression testing to ensure that new changes did not affect existing core functionalities.

⚠ Challenges

  • Some bugs only appeared under specific conditions, making them difficult to reproduce consistently.

💡 Reflection

I realised that fixing or adding one feature could sometimes affect other parts of the system.

Week 15

Objectives Achieved

Conducted functional testing on newly developed features and checked their integration with existing components.

Reported bugs, UI inconsistencies, and unexpected application behaviour to the development team.

⚠ Challenges

  • Testing became more complicated as more advanced features were integrated into the application.
  • Some issues involved multiple components, making it harder to determine the source of the problem.

💡 Reflection

As more features were integrated, I had to pay closer attention to how different parts of the application interacted with one another. Although testing became more challenging, I felt that my experience from previous sprints helped me identify issues more efficiently.

Week 16

Objectives Achieved

Completed and refined test cases for the planned advanced features.

Worked with team members to identify and resolve remaining functional and integration issues.

⚠ Challenges

  • The increasing number of features made testing more time-consuming.

💡 Reflection

This week marked an important stage in our project as we worked towards completing all the planned functionalities. From a testing perspective, I learned the importance of staying organised and keeping track of test results, especially when multiple features need to be verified.
